# heatsync server contract (client side)

source of truth: `heatsync/server/lib/api-catalog/*.ts` (endpoints), `server/services/ws-protocol.ts` (ws types).
distilled from the extension + the chatterino plugin (`heatsync-chatterino`), which already speak this contract in production.

## transport
- origin `https://heatsync.org`. anonymous unless noted. non-bot `User-Agent` (archive search 429s `curl/`, `bot`, …)
- keep status + json body on errors: 429 `retry_after_seconds`, 503 `error`, 404 `error_code:"opted_out"`
- timeouts: 8s lookups, 10s card/emotes, 12s archive search + image probe
- auth (when logged in): `Authorization: Bearer <jwt>`; ws `{type:"authenticate", token}`. bad token → close 4001

## hostile-input bounds
- inventory rows ≤5000 · sender map ≤5000 · url ≤2048, no control bytes · emote name: one token, ≤100, no ws/control, not starting `/` or `.`
- emote dims 1..65535 finite · message text ≤2000 · display name ≤100 · ≤50 emote tokens/message
- chat badges on kick / youtube lines ≤16 per line, names `[a-z0-9_-]{1,32}`, kick `count` (months) 1..1200 else `1` (`badges/relay.rs`) · ≤250 msgs per backfill / youtube batch (keep the tail) · ws `batch` ≤256 · `senderKeys` ≤50 · heat push ≤500 · pin content 500 / name 64
- image host allowlist (https, no userinfo `@`, bare `[\w.-]+` host, exact or `.`-suffix): `7tv.app betterttv.net frankerfacez.com kick.com ggpht.com googleusercontent.com static-cdn.jtvnw.net heatsync.org fourtf.com` (+ `7tv.io`, `cdn.heatsync.org`, `files.kick.com` covered by suffix)

## ws `wss://heatsync.org/ws?b=1`
- anon allowed, no-Origin native clients admitted. json text frames. limits: 30 frames/s, 50 channels/socket, 90s idle
- on open, in order: `channel:join {platform,channel}` per room (a twitch room also `irc:join {channel}`) → `emote:watch {login}` → `ack:channels {channels:[{channel:"kick/<slug>",lastSeq}]}` (kick only, ≤200) → `youtube:subscribe {url,channelId}` per yt source + backfill once per session
- out (authed): `multichat:sync {channels:[{id,twitch,kick,youtube,…}]}` on every tab change made here (add, edit, remove, reorder, /open; ≤50, server refuses more), never for a list the account sent; a change made while the socket was down goes on its next sign-in. `multichat:pull` once signed in at both ends (silent when nothing is saved). new entries are the ext's add-form shape: `id` = twitch, else kick, else `yt-<ms>`; youtube as the bare handle
- out: `channel:leave` (a twitch room also `irc:part {channel}`), `presence:heartbeat` every 25s, `twitch:chat:relay {channel}` (archive demand, ≤1/5min/channel), `youtube:unsubscribe {videoId}`
- in:
  - `batch {messages}` unwrap (≤256, don't recurse)
  - `server:shutdown {reconnectSpreadMs}` → close, reconnect after rand(0, clamp(spread,1000,60000)); no backoff charge
  - `emote:added|removed|emotes:refresh` — `_ch` starts `emotes/` = own inventory → refetch `?v=_seq`; with `username` = another user (global broadcast, reaches anon `?b=1` sockets): `senderKeys[]`, `emoteName`, `ver` → refetch those senders (`&v=`); `removed` tombstones the name now (the ext's removedAt: lines sent before keep it, lines after are text, no slack). a refetch that lacks a name tombstones it too (an unstamped row is just dropped); a fresh row of the name clears the tombstone and keeps the earliest added_at. tombstones count toward the 5000-rows-per-sender cap, oldest evicted first. auto-add-on-send means the add usually lands just AFTER the line, so the refetch must relayout that sender's existing lines
  - `emotes:refresh` (authed, your own sockets only; the server sends it after apply-set, channel-import, shared-set import, undo/redo) → refetch your own inventory exactly like an own `emote:added` (`NetEvent::Inventory`, the sender refetch + relayout of your lines). the payload is never read, so there is nothing to bound; the refetch is the single-flight sender fetch
  - `youtube:delete {videoId, messageIds[], authorChannelIds[], channelId}` (the ext's `applyYtDeletion`) → the youtube lines of that feed whose `id` is listed, or whose `authorChannelId` is listed (a ban takes back the author's backlog), grey out like any delete (kept readable, flagged cleared); lines still waiting in the pacer show first, so nothing deleted arrives untouched a moment later. `channelId` must pass `relay_key` (no room, no effect). ids: ≤256, authors ≤50, each 1..128 bytes with no whitespace or control bytes, the rest dropped (`net/ytdel.rs`); only ever compared to lines held, never shown or sent
  - `settings:delete {key, ts}` and `heat:updated {messageId, newHeat, newMaxHeat, delta, maxDelta}` are ignored on purpose. the ext has no handler for either (its `background.js` only comments on the first; the server declares the type but no route emits it), and the second is the site feed's per-post heat (a base36 post id), which this app has no surface for - chat heat is `user:heat_batch_update`
  - `emote:broadcast {username, emoteName, emoteData{url,width,height,zero_width,nsfw,cw_cats}}` → merge into that sender's map
  - `irc:message {channel, message:{type,id,username,content,…,hsEmotes{word→ref}}}` — heatsync's copy of a twitch line in a room we `irc:join`ed (every line, so busy rooms send twice): frames without `hsEmotes` are skipped before parsing. never shown as a line (our irc has it): its refs merge into our line of the same id, by name, never over a name the line already has, and only that row lays out again. refs that beat the line wait by id (≤256, 30s)
  - `kick-chat-message {data:{id,username,displayName,content,color,timestamp,hsEmotes{word→{url,provider,zeroWidth,nsfw,cw_cats}},replyTo}, _ch, _seq}`; `kick-chat-backfill {channel, messages}`
  - `youtube:chat {channelId, messages[{id,user,text,emotes[{alt,url}],timestamp,color,amount,systemMsg,authorChannelId,hsEmotes}], replay}` — drop `replay:true` batches
  - `youtube:status {channelId,status:connected|ended|not-live|chat-off|no-slot|error,videoId}` — yt subscribe ≤5/60s; retry ~120s
  - `follow:live:snapshot {streams}` (authed, once after `authenticated`, cache-only so a cold cache sends nothing): the followed-live list gains/refreshes those rows, never loses one. `follow:stream:online|offline|update {platform,channel,displayName?,game,title}` keep it current (online adds a row, update changes game/title of a row it has, offline drops the channel's leg or the row). the list is `model/following.rs`, shown by `app/following.rs` (ctrl-b, `/following`, `/live`)
  - `stream:online|offline|update {platform,channel,game,title,prevGame,prevTitle}`, `pin:set|clear`, `moment:spike {platform,channel,id,rate,baseline,game,title}`, `user:heat_batch_update {updates[{username,userHeat,op,re}]}`
  - `account:changed` (authed, exactly `{type}`: a platform was linked or unlinked, or your sub flair was set or cleared) → re-read the account (`me`, twitch id, chat token) now, and ask again about every flair held (they keep showing until the answer). also on every `authenticated` of a later socket after the first sign-in: one sent while we were away is lost
  - `multichat:config {channels, rev}` (authed: right after `authenticated`, on `multichat:pull`, and to every socket of the account on each `multichat:sync`, the sender's included) → your channel tabs (`model/tabsync.rs`). `channels` not an array → dropped whole. entries: the ext's `isValidSyncedChannel` (twitch `^[a-zA-Z0-9_]{1,25}$`, kick adds `-`, youtube `^@?[\w.-]{1,100}$` or `https://(www.)?youtube.com/…`, no CR/LF; a falsy leg is absent) plus a string `id` ≤64 and ≤2KB of json each; bad entries dropped, ≤50 kept. `rev` (`user_settings.multichat_rev`) gated like the ext's `isStaleConfigRev`: older than the newest applied for this account → dropped, no rev → applied. the account's list replaces the tabs (the ext's rule on sign-in, never merged); entries go back untouched (`youtubeExplicit`, `preview`, anything newer) except `sendTargets {twitch?,kick?,youtube?}` (a missing key = on), which is the tab's send choice: read onto the tab on every frame, written back in that shape by ctrl-n and alt-t/k/y with its other keys kept (`model/sendto.rs`), and one with no feed this app opens (a UC-only youtube) stays in the list without a tab. an echo of our own send changes nothing. ignored while logged out and in a run given channels on the command line
  - `seen:update {surface: mentions|whispers|live|inbox, at}` (authed) → your other client looked: out goes that tab's light unless something newer landed. ms epoch, `0 < at ≤ 9999999999999`. `inbox` (the site's dm badge time, `inbox_seen_at`) is ignored both ways: it is not the notifications' read state (that is `POST /api/notifications/mark-read`)
  - `notification:new {kind, message_id?, content?, from_username?, parent_is_op?, url?, …}` (authed, flat: the envelope's `type` shadows the notification's own, so only `kind` says what it is) → a row in the mentions tab (`model/inbox.rs`, the ext's `hsNotifIn`): from `heatsync`, tagged `[H]`, text per kind as `hsNotifText` (`reply` → `replied to your post|reply|you[: text]`, `mention` → text or `you were mentioned in a post`, `feedback_fixed` → text or `your report was fixed`, `anonymous: ` first when anon). only those three kinds are rows; any other (`system`, `follow`, …) is dropped. a row joins the mentions buffer and its 500 cap, lights the tab, pings/flashes/notifies like a mention, is kept in the mentions file (id `hsn-<kind>-<ms>-<post>`, read back bounded) and enter or a click opens its post in the feed tab. content ≤300 chars, control bytes out, `message_id` base36 ≤8. `from_username` is only ever `Anonymous`
  - `chat:origin_broadcast {text, channel?, origin: "heatsync", sendId?, ts}` (authed, only to your own sockets: heatsync.org sent a line for you) → the echo of it on twitch/kick/youtube wears `[H]` instead of `[T]`/`[K]`/`[Y]`, even with platform tags off (`model/origin.rs`). matched by text (kick `[emote:id:name]` tokens read as names) on your own lines only (any linked name), for 24h, ≤64 kept, text ≤500 chars; an echo that beat the frame by ≤10s is tagged after. one send's other legs fold into the row already shown (model::sentfold, 10s), except when two legs both landed before the frame
- reconnect: backoff `min(60, 2^min(n,6))s × 0.8..1.2`, reset only after a ≥30s session. watchdog: recycle if no frame 90s or handshake >30s. generation token — late frames from a dead socket are dropped. gap >60s → mark sender caches stale + refetch pins. track max `_seq` per `kick/*`

## render rules
- heatsync emote renders iff the sender's own inventory has the exact-case whitespace token, `height>0`, msg time within `[added_at−120s (−15s on your own lines), until+120s)` and before any removal tombstone, not locally blocked, ≤50/msg
- relayed `hsEmotes` are server-computed from the sender's inventory — look up only the words present
- cw gate: skip `nsfw` or `cw_cats` ∋ `sexual|gore` unless the viewer opted in (`viewer_show_*`)
- size: scale by height only — cdn 1x is ≤32px tall but stored dims are native; never trust stored width. 7tv `.avif` → `.webp`
- heat bar: hidden <5. tiers 5 `▎` white · 20 `▍` white · 50 `▍` yellow · 100/200/500 `▌` yellow · 1000/5000 `▊` red. twitch lines only. never 🔥 beside it
- marker order before name: chatterino badge, sub flair, 🔥 (known heatsync user), heat bar. twitch lines only (`ui/chat_view/marks.rs`, decided by `heatsync/marks.rs`). the 🔥 and the bar never sit together: a bar shows → no 🔥 (someone with heat ≥5 is plainly on heatsync); 🔥 only for a known user under 5. known = we hold a non-empty emote set for the sender (never asked for just this); your own line counts as known, even before your set loads. switches `flame`, `heat_bars`, `sub_flair` (all default on, local: the ext has no key for them)
- stream-event rows from the ext's hermes toggles: `new prediction up — <title>` (`event-pred`, switch `ev_pred` = hermesEvents `pred`, the banner's own) when a channel's prediction poll (the banner's gql ask, no new request) shows a NEW open prediction id; never on a channel's first answer, never twice for one id. in that channel's own tab. there is no poll row: the ext's `poll` rows come from twitch's page traffic and kick's pusher, neither of which this app reads (twitch has no public poll query), and the server never relays them
- twitch `announcement` rows are one style: the ext parses `msg-param-color` but never draws it (one yellow `announce` row), so this app does the same
- modifiers: `w! h!/x! v!/y! z! c! l! r! p! s!`, `ffzX ffzY ffzW ffzWide ffzTall ffzCursed ffzHyper ffzRainbow ffzBounce ffzJam ffzSlide ffzArrive ffzLeave ffzSpin`, tint `c!#hex`. prefix or postfix, chainable, token word hidden. grammar: ext `src/lib/modifiers.js`
- threadlink `>>id` → `https://heatsync.org/thread/<id>`

## 7tv EventAPI `wss://events.7tv.io/v3`
- one socket, opened only while a channel is joined and has a 7tv set. frames ≤512KB. hello → `subscription_limit` (we cap at 120) + `heartbeat_interval`; 3 missed beats → recycle
- subscribe (op 35) / unsubscribe (op 36) `{type, condition:{object_id}}`: `emote_set.update` per channel set (deduped, a twitch+kick pair can share one), `user.*` per broadcaster + us → `CosmeticsStale`
- `emote_set.update` body: `pushed` / `pulled` / `updated` items with `key:"emotes"`, ≤200 each, ids `[A-Za-z0-9]{1,40}`, urls are built by us on `cdn.7tv.app`. `updated` = rename / flag change
- reconnect: backoff as heatsync ws, reset after ≥30s; after any reconnect each set is refetched whole (`/v3/emote-sets/<id>`) because deltas were missed
